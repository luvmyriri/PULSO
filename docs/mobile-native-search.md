# Native resident search and system bars

Implemented for the resident APK. Desktop search retains its existing composition. The mobile Home search control opens an opaque, full-screen native HTML dialog rather than a dropdown over dashboard cards. The control and focused search field use the primary orange token, without the resident theme's green-mapped blue utility classes. The input has one focus boundary on its container, with space around it to avoid clipping.

The panel provides a back control, a clear-query control, recent searches, quick actions and grouped report/update/help/hotline matches. Group names, empty states, live counts and controls support English and Filipino. Empty history is genuinely empty; it is not seeded with sample searches. Search consumes the same resident-scoped, already loaded report/publication data and existing selection callbacks. It introduces no search endpoint, permissions or external calls. Loading and unavailable city-update notices are kept separate from no-match results. Existing hotline content is retained, not newly verified by this change.

The dialog traps focus, focuses the input on entry, dismisses with Escape or Android Back, and restores focus/scroll on cancellation. Selecting a destination does not restore the old scroll position over the newly opened page. Results have native buttons, section headings, live counts and clear labels. The visual viewport controls panel height while the keyboard is open; only results scroll, leaving the search field visible. Controls retain 44 px targets. Narrow, enlarged-text and forced-color layouts have explicit styles.

Dashboard and full-screen search surfaces declare `data-native-system-bar-surface`. Android's top-bar color comes from that stable background rather than whichever scrolling card or button touches the viewport edge. Landing/briefing edge-to-edge treatment and immersive camera visibility remain independent. The bottom-bar appearance policy is unchanged.

Dashboard Home also declares `data-native-dashboard-home` to draw behind transparent system bars. A fixed, non-interactive canvas surface keeps content from scrolling behind the status icons while the header hides; its color matches the Home header in both themes. The greeting and bottom navigation consume native safe insets, including the More menu's offset above navigation. Other dashboard pages retain their reserved native insets. The Home header omits its theme-cycle icon; theme preferences remain available in Account settings.

The Home avatar/greeting opens Account & Profile. Retapping Home, My reports or Updates smoothly scrolls the current destination to the top. While Account/Profile is scrolled, tapping its active More control uses the same transition without resetting the current account subpage; the menu remains available when already at the top. Reduced-motion preferences use an immediate return. Other destinations retain their saved scroll positions when returning normally.

Validation uses synthetic residents, bridge calls and API responses in `frontend/tests/resident-settings.browser.mjs`, including an orange control at the top edge, orange search focus, keyboard-height resizing, clearing, Escape/Android Back, destination selection, both themes/languages and enlarged text. The existing camera browser harness checks immersive open/close behavior. These checks do not claim physical-phone installation or keyboard validation. No Figma change was made; live-file reconciliation remains pending access.
